# Установщик ZAPRET

Используется штатный NSIS из Tauri: без WPF, дополнительного EXE и собственного
движка обновлений. Фирменное оформление задаётся в `branding.nsh` и BMP-ресурсах:
фон #070D1F, текст #DFE4FE, лавандовая надпись Inter и существующая иконка.
Поля и кнопки остаются стандартными Windows. Русский и английский выбираются
по языку системы. Версия установщика берётся из `src-tauri/tauri.conf.json`.

## Сборка

```powershell
npm run installer:build
# Без ключа updater, только для локальной проверки:
npm run installer:build -- -Unsigned
```

Результат: `src-tauri/target/release/bundle/nsis/ZAPRET_<version>_x64-setup.exe`.
Отдельной команды упаковки поверх Tauri больше нет. Обычный `npm run tauri build`
тоже включает оформление: настройки находятся в `tauri.conf.json`.
Файлы BMP хранятся в Git; генерация не нужна при каждой сборке.
Для обновления изображений: `npm run installer:assets` (Windows, System.Drawing).

## Предпросмотр и проверки

`npm run installer:preview` компилирует
`artifacts/installer/nsis-preview.exe` установленным Tauri-компилятором NSIS.
При нестандартном расположении передайте `-MakeNsis <path>` скрипту
`scripts/preview-installer.ps1`. Это макет страниц без полезной нагрузки,
записи реестра и запуска приложения; он проверяет оформление, а не установку.

`npm run test:installer` проверяет манифест, совместимость платформ и ручную
пересборку релиза. Манифест отклоняет старую WPF-оболочку и несовпадающую версию.

## Обновления и GitHub Actions

Штатный Tauri NSIS обрабатывает `/P /R /UPDATE /ARGS`: пропускает страницы выбора,
показывает ход установки, закрывается по завершении и перезапускает приложение.
`/S` остаётся тихим режимом. Новых пользовательских подтверждений мы не добавляем.
UAC и ошибки по-прежнему контролируются Windows и Tauri.

Workflow собирает NSIS и MSI, подписывает их прежним ключом updater Tauri,
создаёт latest.json из локальных подписей этой сборки и загружает его в релиз.
Ключи `windows-x86_64` и `windows-x86_64-nsis` указывают на штатный EXE.
`windows-x86_64-msi` сохраняет MSI. После загрузки замены и манифеста workflow
удаляет только устаревшие `ZAPRET_<version>_x64-branded-setup.exe` и его `.sig`
из того же релиза, если они там есть.

Для пересборки: Actions → publish → Run workflow, выбрать ветку исправлений,
указать существующий тег (например v26.9.4). Workflow должен присутствовать
в основной ветке. Версия ветки должна совпадать с тегом. Тег не перемещается,
используется код выбранной ветки. Более старые клиенты получат исправленный
установщик при обновлении. Пересборка релиза с тем же номером не вызывает
повторное автообновление.

## Проверка детектов

Сравнение опубликованных файлов и ограничения зафиксированы в
[отчёте](../docs/installer-antivirus-review.md). Проверить вложение без запуска:

```powershell
node scripts/compare-installer-payload.mjs <old-wrapper.exe> <standard-nsis.exe>
```

Подпись updater не является Authenticode. Изменение упаковки не гарантирует
нулевые детекты. Для сравнения VirusTotal нужен именно конечный EXE из CI;
локальная сборка может включать частные параметры из .env через build.rs.
Не загружайте такой локальный артефакт в публичный сервис без проверки состава.

Перед публикацией требуется проверка в чистой Windows: установка и удаление,
обновление с прежнего NSIS, оба режима доступа, перезапуск и машина без WebView2.
Локально выполнена сборка NSIS и проверка макета страниц; установленное на рабочем
компьютере приложение не изменялось. Эти проверки не заменяют полный цикл в VM.
