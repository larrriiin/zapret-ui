# Фирменный установщик ZAPRET

Нативная оболочка WPF (.NET Framework 4.x, Windows x64) в палитре приложения:
фон `#070d1f`, акцент `#ba9eff`, локальный Inter и иконка ZAPRET. Повторяет
короткий сценарий первого запуска: подготовка → установка → готово.

Внутри одного EXE находится неизменённый NSIS-пакет Tauri. Оболочка запускает
его с `/S /currentuser` или `/S /allusers`, передавая папку через последний
аргумент `/D=`. Файлами, ярлыками, регистрацией удаления и WebView2 управляет
NSIS. Сам интерфейс WebView2 не требует. Загрузка WebView2 может потребовать
интернет; оболочка не является полностью автономным пакетом зависимостей.

## Сборка

Из корня репозитория на Windows:

```powershell
npm run tauri build -- --bundles nsis
npm run installer:build
```

Результат: `artifacts/installer/ZAPRET_<version>_x64-branded-setup.exe`.
Скрипт проверяет совпадение версии NSIS с `tauri.conf.json`. Для нестандартной
папки сборки передайте `-Payload <path>` в `scripts/build-installer.ps1`.
Не используйте старый NSIS-пакет: оболочка подтверждает установленную версию
по реестру и наличию `zapret-ui.exe`.

Локальная сборка без ключа подписи обновлений:

```powershell
# Сохранить вне src-tauri, например artifacts/installer/local-build.json:
# {"bundle":{"createUpdaterArtifacts":false}}
npm run tauri build -- --bundles nsis --config artifacts/installer/local-build.json
npm run installer:build
```

## Безопасный предпросмотр и проверки

```powershell
npm run installer:preview
# Открыть созданный *-setup-preview.exe — установка в этой сборке отключена.
npm run test:installer
# Любой EXE также поддерживает:
# --preview           показать сценарий без установки
# --render <directory> сохранить четыре экрана WPF в PNG без открытия окна
```

Engine-тесты запускают безвредный вложенный EXE, который записывает только
командную строку в тестовую папку. Проверяются пути с пробелами и кириллицей,
недопустимые пути, передача параметров, коды завершения и очистка временного
пакета. Реестр, ярлыки и установленное приложение тесты не меняют.

## Поведение

- Существующая установка ищется в HKCU/HKLM, в обоих представлениях реестра.
  Её папка сохраняется; новую папку можно выбрать при первой установке.
- Более новая установленная версия блокирует понижение через оболочку.
- Перед установкой пользователь должен закрыть ZAPRET, включая трей.
- Для установки всем пользователям повышается только вложенный NSIS.
  Оболочка и последующий запуск приложения остаются в исходном контексте.
  Если сама оболочка запущена от администратора, вместо запуска приложения
  она предлагает закрыть установщик и открыть ZAPRET через меню «Пуск».
- Папки установок разных режимов не могут совпадать или быть вложенными.
- На небольших экранах окно ограничено рабочей областью; основная часть
  прокручивается, кнопка установки остаётся доступной внизу.
- Во время работы NSIS закрытие оболочки заблокировано. Проценты не
  моделируются: показывается неопределённый прогресс и текущий этап.
- Отмена UAC, ошибка NSIS и отсутствие установленной версии ведут на экран
  ошибки с возвратом к настройкам. Код 3010 требует перезагрузки; оболочка
  сама не перезагружает Windows.
- Временный пакет помещается в уникальную папку с ограниченными ACL,
  проверяется по встроенному SHA-256 и удаляется после завершения процесса.
  SHA-256 проверяет целостность вложения, не заменяет Authenticode.

## Автообновление со старых версий

Оболочка понимает прежний протокол Tauri `/P /R /UPDATE /ARGS ...`.
При `/UPDATE` она сразу показывает экран прогресса, запускает вложенный
NSIS с `/S /UPDATE /R` и закрывается после успешного завершения. Нет выбора
папки, кнопки установки или финального подтверждения. Папку и режим установки
восстанавливает штатный NSIS; он же запускает приложение через `RunAsUser`.
Исходные аргументы приложения после `/ARGS` передаются без изменения.
Режим `/S /UPDATE` работает без видимого окна; при ошибке появляется описание.
Системный запрос UAC, если он требуется NSIS, остаётся под контролем Windows.

В сборке предпросмотра можно безопасно проверить этот сценарий:

```powershell
& ./artifacts/installer/ZAPRET_26.9.2_x64-setup-preview.exe /P /R /UPDATE /ARGS
```

## Релизы и ограничения проверки

Workflow создаёт draft-релиз, собирает фирменный EXE, подписывает его тем же
ключом updater Tauri и обновляет `latest.json`: `windows-x86_64` и
`windows-x86_64-nsis` указывают на подписанную оболочку. Публикация происходит
только после загрузки EXE, подписи и готового манифеста. Уже выпущенные
EXE-версии получают новый интерфейс без промежуточного обновления клиента.
Явная запись `windows-x86_64-msi` и другие платформы не меняются; миграция MSI
на NSIS в этой работе не вводится. Стандартный NSIS также остаётся доступным
для ручной загрузки. Удаление остаётся стандартным NSIS; UI пока на русском.

Новый внешний EXE требует отдельной Authenticode-подписи, если подпись
дистрибутивов будет настроена; ключ updater Tauri её не заменяет.

Перед выпуском следует проверить в чистой Windows VM: новую установку,
обновление прежнего NSIS (и переход с MSI), оба режима доступа, отмену UAC,
машину без WebView2 и удаление через «Установленные приложения». Engine-тесты
не заменяют эти интеграционные сценарии и не запускают реальную установку
на рабочем компьютере разработчика.
